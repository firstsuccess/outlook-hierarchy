# Sites内のアクセスカウンター

サポートページだけに同一オリジンの `/api/support-counter` を使用します。Hitsへの通信は廃止しました。

- 初回の表示は20。以降のページ表示で21、22…と増加します。再読込・動作確認・ボットのJavaScript実行も含む表示回数で、ユニーク人数ではありません。
- Sites管理のD1に固定キーsupportと数値valueだけを保存します。社員情報・ExcelのURL・IPアドレス・ユーザーID・トークンは保存しません。
- POSTで原子的に加算し、GETは加算せず確認するだけです。クロスオリジンのPOSTを拒否します。エラー時は架空の数値を表示しません。
- 再デプロイで初期値に戻りません。既存データのあるカウンターをリセットする処理や公開管理APIはありません。

`npm run build` は従来通り静的ファイルを生成します。Sitesでカウンターを使用する場合は `npm run build:site` で静的資産を埋め込んだWorkerを追加生成します。静的ホストだけに配置した場合はカウンターAPIがないため、カウンターは取得失敗の表示になります。Sitesが実行・保存領域を管理するので、利用者や提供者のPCでNode.jsを常駐させる必要はありません。

スキーマはdb/schema.ts、マイグレーションはdrizzle/で管理します。変更時は `npm run db:generate`。公開時にSitesが適用します。CREATE TABLE等をリクエスト処理の中では行いません。

カウンターの追加は、当初の静的構成に対する利用者承認済みの例外です。アドイン自体は引き続きMicrosoft GraphとOffice.jsを利用し、社員情報をSitesの保存領域へ送信しません。
